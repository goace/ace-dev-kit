# 项目知识库使用规则

本文档规定agent如何从项目知识库中获取跟当前任务相关的必要的信息。

## 开始探索前先读这些

- 根目录的 `GLOSSARY.md`。
- 根目录 `docs/adr/` 中影响当前任务的 ADR。

上述文件不存在时静默继续。不要因为它们缺失而中断工作，也不要仅为了补齐布局就提前创建空文件；术语表和 ADR 应在确实有内容需要记录时按需创建。

## 知识库目录布局

```text
/
├── GLOSSARY.md
├── docs/
│   └── adr/
│       ├── 0001-event-sourced-orders.md
│       └── 0002-postgres-for-write-model.md
└── src/
```

## 使用术语表中的词汇

当输出中出现领域概念时，使用 `GLOSSARY.md` 中已经约定的术语，不擅自用同义词替代术语表明确避免的说法。

如果所需概念尚未出现在术语表中，先判断是在臆造项目并未使用的语言，还是发现了真实的领域缺口；不要静默引入新的同义词。

## 暴露 ADR 冲突

如果当前方案、输出或实现与已有 ADR 冲突，必须明确指出冲突及其原因，不要静默覆盖既有决策。例如：

> 与 ADR-0007（事件溯源订单）冲突，但由于……值得重新审视该决策。
